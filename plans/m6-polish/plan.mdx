### Summary

After this change, retrievability stops penalising live memories, stale facts clear through explicit supersession, link thresholds sit on the store's real similarity scale, and `go run ./cmd/eval` states which query mix and which store cost its recommendation rests on. The README then says only what the new tables support. This delivers the eval-correction and README parts of milestone M6. Capabilities added: `recall-ranking`, `memory-supersession`, `similarity-thresholds`. Capabilities modified: `eval-dataset`, `eval-harness`, `eval-ci-gate`, `memory-store-fake`. Out of scope: `memory_stats` and the demo recording (see Open Questions), changing the `ENGRAM_DECAY` default, the `-rerank cosine` secondary table, sweep cost in the report, similarity-based staleness detection, and everything on the v2 list.

The report will look like this. The bracketed values are unknown until the first run.

<Callout id="key-finding" tone="warning">

**After this change, forgetting cannot beat never-forgetting on retrieval in any query class.** Supersession runs in every arm, and recall drops superseded memories in every arm, so `none` no longer has stale facts to trip over. Its fact nDCG should climb from 0.673 toward 1.0, level with `type-aware`. The store weight then decides A versus C. A rough estimate on the agent mix puts `none` near 0.98 and `type-aware` near 0.87 at about 30% of the store, so the break-even lambda is near 0.16. That makes the lambda value a decision about what the recommendation will say, so it belongs in Open Questions before the first run.

</Callout>

### Retrieval: filter first, tiebreak only

The M5 run showed a permanent standard (R = 1) outranking a two-day-old episode the caller asked for: episode-recent nDCG 0.661, and episode access hit rate 0.412 against 0.989 under `none`. Two changes fix that. `defaultWRet` drops from 0.5 to 0.01, so R can reorder only memories already within 0.01 of each other. It stays a plain scalar so the sort remains a total order; a "within 0.01" comparator is not transitive and would break `sort.Slice`. Under `NullDecay` R is constant, so arm A's order is exactly sim + 0.3 importance.

The filter also moves ahead of the pool cut, because a filter that runs after truncation still lets dead memories take pool slots.

### Supersession that actually replaces

`remember` applies `Supersedes` to semantic writes as well as procedural ones, and the generator sets it on every fact chain. Detection by similarity stays v2. An episodic write's `Supersedes` is treated as absent throughout, so it cannot affect dedup. Recalling a chain-mate no longer refreshes an old version: `PropagateReinforce` skips superseded targets in both stores, using one Cypher predicate on a property Neo4j already holds, and skipped targets do not consume the cap of 20.

There is also a data-loss bug on this path that the eval could never show. `doRemember` dedups and returns before it applies `Supersedes`. A correction such as "deploys on Tuesday" to "deploys on Thursday" can embed above raw cosine 0.90, and then the new content is dropped, the old memory is reinforced, and the replace never happens. The generator's chain band stays under 0.90, so no eval run would reach this. Dedup now skips a candidate that is already superseded or named in `Supersedes`, and supersession applies on the dedup path too, which also makes a retried correction idempotent.

### Thresholds on the real scale

The Neo4j index returns (1 + cos) / 2, so the M1 and M2 constants meant less than they appeared to. M4 set `propagateThreshold` equal to `linkThreshold`, and this keeps that relation. Explicit links stay at weight 1.0 and always propagate. Stored edges keep their weights, so those below 0.925 still expand and stop propagating; no migration runs.

The auto-link point moves to raw 0.85, so generator twins need their own band of [0.86, 0.89] to keep auto-linking without deduping. `sigmaTwin` drops from 1.5 to roughly 0.95, tuned against `TestTwinRange` only. Chain versions keep [0.74, 0.88]. Expect fewer edges than M5's 1,048 in every arm.

### The instrument: named mix and store cost

The M5 mix decided the M5 winner while staying hidden: 40% of queries asked for things the design means to forget. `Params` gains `Mix`, so the baseline records it and the existing stale guard catches a mismatch with no new code. Each mix is its own simulation, because a query reinforces what it returns, so re-weighting one run would misreport the store. `-mix` picks one per invocation and the README carries both tables.

<Table

  rows={[

  ]}

`agent` is an assumption, not a measurement: no real agent traces exist yet. An agent mostly asks for the current way of doing something and for what just happened, sometimes for a fact, and rarely for old chatter or a multi-hop association.

The recommendation score is nDCG minus lambda times (store / store of `none`). Lambda defaults to 0.10, printed in the table, overridable with `-lambda`, and `-lambda 0` gives the retrieval-only answer. The tie rule stays: within 0.005, the smaller store wins. Store cost is a value judgement, because the in-memory fake has flat latency and measures nothing here. The report therefore also prints the lambda at which each decaying arm ties `none`, so a reader can apply their own.

### Effect on the A/B/C comparison and the CI gate

The gate's logic does not change: arm C against its own past, never against A or B, tolerance 0.02. Numbers move, so it is red by design from the ranking task until the re-baseline task. A baseline with no `mix` counts as stale rather than as a regression.

### Verification

`go build ./...`, `go test -race ./...`, `golangci-lint run ./...`, then `go run ./cmd/eval --update-baseline -seed 42` on amd64 and `go run ./cmd/eval --ci` twice with byte-identical arm C rows. Tables come from `-seed 42 -seeds 1` on `agent`, on `-mix stress`, and with `-lambda 0`, and they go into `design.md` beside the predictions. `go test -race -tags=integration` runs against Docker Neo4j to exercise the Cypher predicate. The one PR carries code, archive and synced specs; "ready to merge" is said only once the archive commit is on the branch.
