### Summary

This change finishes milestone M6 apart from the recording. After it, `memory_stats` exists as the fourth MCP tool, a kept transcript shows Claude Code using all four tools over stdio across separate processes, and `docs/demo.md` holds the exact commands and prompts for recording the demo. PRD sections 8 and 9 make a real agent using the server the v1 acceptance condition; nothing has ever spoken stdio to `engramd` in a test or a kept run.

Capabilities added: `memory-stats`, `agent-acceptance`. Capabilities modified: `tools-entry`, `memory-store-fake`. Out of scope: the recording itself, persisting sweep stats, changing when the sweep runs, a namespace whitelist, recent access patterns, the `blend` discontinuity, the `ENGRAM_DECAY` default, a CI integration job, the `supersedes` typo and cross-namespace gaps, and everything on the v2 list.

**This change does not move the eval.** `Recall`, `Remember` and `SweepOnce` are untouched, and no eval constant, mix, weight or dataset changes. A/B/C and the CI gate are unaffected. Verify proves it: `go run ./cmd/eval --ci` passes and `eval/baseline.json` is unchanged, with no re-baseline.

**Sweep stats will read empty almost everywhere, including the demo.** A stdio client starts `engramd` per session, `Run` waits one full hour before its first tick, and nothing is persisted. The tool description says so.

### What gets counted

Counts come from exact Cypher aggregates and the histogram comes from a capped fetch of rows, because retrievability lives in `DecayModel` and cannot run in Cypher. Deriving counts from the capped rows would make every count silently wrong above the cap.

<Table
  id="counted-sets"
  columns={["Field", "Set it covers", "Notes"]}
  rows={[
    ["counts.total, store_size.memories", "All rows in scope", "One fold, so they cannot differ"],
    ["counts.by_type, counts.by_namespace", "All rows in scope", "TypeCounts structs: the schema names the keys and no inner map can be nil"],
    ["counts.live", "Neither superseded nor forgotten", "The set recall can return by default (mcp/recall.go:259)"],
    ["counts.superseded, forgotten, pinned", "Their flags", "They overlap: a row can be superseded and forgotten"],
    ["retrievability.buckets", "Live rows, capped at 10,000", "Ten fixed-width, top closed so R = 1.0 lands in it. Buckets sum to live unless truncated"],
    ["retrievability.below_recall_threshold", "Live rows, capped at 10,000", "R < 0.05, the test recall applies. Bucket 0 spans [0, 0.1), so it cannot show this"],
    ["store_size.link_edges, entity_bridges", "Touching the namespace", "Distinct pairs, matching the eval's edges and bridges columns"],
    ["sweep.*", "Whole store, since process start", "Never follows namespace. last_run_at is null before the first completed pass"],
  ]}
  density="compact"
/>

The row cap orders by id. Ids are 128 random bits, so the first 10,000 by id are a uniform sample over age and type, and a truncated histogram stays unbiased. Ordering by `last_accessed` would bias it toward fresh rows. Rows carry no content or embedding, so the fetch is bounded by the cap, not by stored text.

An unknown namespace returns empty counts, not an error. Every map is initialised and every bucket built, because of what the SDK does with nil values on v1.6.1, probed in a throwaway module:

### How it is built

No new package. `ServerStore` gains two read methods through a narrow interface at its consumer, following `forgetStore`. The types live in the root package because `neo4j`, `mock` and `sweep` all produce them and adapters must not import each other. Sweep stats reach `mcp` through a function-valued option, following `WithIDGenerator`, so `mcp` never imports `sweep`.

`LiveMemories` reuses `engram.Memory` with empty `Content`, `Source` and `Embedding` rather than a new row type, which is how `PruneCandidates` and the recall projections already work. It projects `content: ''` and `source: ''` so `mapToMemory` keeps its required-property checks. The architect approved these types and interfaces with no blocking finding.

**Strictly read-only, enforced by the server.** All the stats queries run with `ExecuteQueryWithReadersRouting()`. A `SET` through that option on Neo4j 5.26 Community fails with `Writing in read access mode not allowed`, so a mistake in the Cypher cannot write. The interface also has no write method, and tests compare memories before and after on both stores.

The entity-bridge count is exact and quadratic in a hub entity's mentions, so its query shape matters. Measured on a scratch `neo4j:5.26-community` at default memory settings with 5,000 memories, net of `cypher-shell` startup:

<Table
  id="bridge-cost"
  columns={["Query shape", "2.0M pairs", "12.5M pairs", "Exact?"]}
  rows={[
    ["Plain count(DISTINCT [a.id, b.id])", "about 10 s", "about 131 s", "Yes"],
    ["Per-memory subquery (chosen)", "not measured", "about 20 s", "Yes"],
    ["Per-entity sum(n*(n-1)/2)", "not measured", "under 0.1 s", "No: overcounts pairs sharing two entities"],
  ]}
  density="compact"
/>

The chosen query matches the eval's `bridges` column and holds one memory's distinct set at a time. A 5,000-mention hub is rare in a single-user store and costs 20 s on an operator call. It carries a `shortcut:` comment naming the per-entity sum as the fallback.

### A real agent, end to end

<Callout id="feasible" tone="success">

Probed against today's `engramd` and the real stack: headless `claude -p` works here. The agent chose `remember` in one process, then `recall` and a hard `forget` in a second. That run used the three existing tools and was not kept; the kept transcript comes from a later run with all four.

</Callout>

**Wiring.** No tracked `.mcp.json`. A tracked file affects every session in this repo, with the stack down the client sees only `calling "initialize": EOF`, and `go run` recompiles on each start. Instead:

<Code
  id="wiring"
  language="bash"
  code={"go install ./cmd/engramd                            # puts engramd on PATH via $(go env GOPATH)/bin\nclaude mcp add --scope local engram -- engramd      # per person, tracks nothing\n\n# The transcript and the demo leave no state and hide every other MCP server:\nclaude --strict-mcp-config --setting-sources \"\" \\\n  --mcp-config '{\"mcpServers\":{\"engram\":{\"command\":\"engramd\"}}}' \\\n  --allowedTools 'mcp__engram__*'\n"}
/>

**Stdio smoke test.** `TestStdioAllTools` in `cmd/engramd`, behind the `integration` tag, builds the binary with an `.exe` name on Windows and drives it through `mcpsdk.CommandTransport`. It maps the `*_TEST_*` variables, including user and password, to what `engramd` reads, so an override cannot send it to the dev database. It skips with `neo4j unavailable` or `tei unavailable` after a direct reachability check, rather than failing on `initialize: EOF`. It decodes into `map[string]any`, so it asserts the JSON keys a real client sees.

CI does not run integration tests, so an in-memory transport test in `mcp/` also covers the wire shape.

**The kept run.** Three `claude -p` processes in namespace `demo/m6-e2e`, from a temp directory so no `CLAUDE.md` or repo path enters the session, with built-in tools off. The prompts name no tool:

**Publishing is whitelisted, because this repo is public.** A script outside the repo keeps only assistant text, tool calls, tool results and the result status. The init event, session ids, uuids, usage and thinking never get through. Then a negative search for the local user name, GitHub login, email, drive and home paths, other MCP server names and any namespace other than `demo/m6-e2e` must find nothing. A run where the agent lists other namespaces is discarded and repeated, never edited.

**The demo script.** `docs/demo.md` gives every command in order from a stopped stack, with what the viewer should see at each step. It warns that unscoped `memory_stats` lists every namespace. The commands get run once from Git Bash, with `claude -p` for the agent steps, because the interactive UI cannot be driven from here; `verify.md` discloses that.
