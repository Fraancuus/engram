### Summary

After this change, `go run ./cmd/eval` generates a seeded synthetic, graph-structured dataset (3 namespaces, 50 topics, 5,000 memories, 1,1,200 entities (a minimum; the generator grows the pool to keep entity fan-out under 20), 500 queries, 180 virtual days, 64 dimensions), replays it through the shipped `mcp` recall pipeline three times, and prints one comparison table plus a recommendation. The arms differ only in the `DecayModel`: A is `none` (`NullDecay`), B is `uniform` (`UniformDecay`), C is `type-aware` (`TypeAwareDecay`). `go run ./cmd/eval --ci` runs the floor-size dataset with the baseline seed and fails when arm C precision@5 drops more than 0.02 below `eval/baseline.json`. The strategy also becomes an operator option: `engramd` reads `ENGRAM_DECAY`. Capabilities covered: `eval-dataset`, `eval-harness`, `eval-ci-gate`, `memory-store-fake`, `tools-entry`, `decay-strategy-option`. Out of scope: `memory_stats`, the README write-up and demo (M6), a public benchmark, a sidecar or Neo4j backed run, runtime auto-tuning, ablation arms, tuning decay constants.

The numbers below are illustrative only, to show the shape of the output; real values come from the first run.

### Eval architecture

`eval.Run` builds a fresh arm per decay model and seed. Every arm uses the same wiring and the same dataset; the only substituted part is the `DecayModel`. The eval calls the same handler code the MCP server wraps, so the thing measured is the thing shipped. The reranker is a cosine scorer over the generator's own vectors and never sees labels, so nothing judges itself.

### Dataset shape and the virtual-day loop

The dataset is generated directly as unit vectors with structure (no text embedding), so the arms share identical geometry and the generator owns the ground truth. Content strings (for example `t017/std/v2`, `t017/fact/3`, `t017/ep/0412`) exist because `remember` requires content and double as the embedder lookup key.

### Hard-to-reverse decisions

<Callout id="decisions-hard" tone="decision">

These shapes are consumed by later code or by CI, so changing them after merge is expensive.

- **`mcp` exported API.** `mcp.Tools`, `mcp.Option`, `mcp.WithIDGenerator`, `mcp.NewTools(...)`, `mcp.ServerStore`, and the exported DTOs. `NewServer` changes signature to `NewServer(t *Tools)`. This widens the package API; the `architect` agent reviews it in Task 4.
- **`ENGRAM_DECAY` names.** Exactly `type-aware` (default), `uniform`, `none`. An unknown value is a startup error.
- **`eval/baseline.json` schema.** `k`, `seed`, `goarch`, `params`, `precision_at_k`, `ndcg_at_k`; 4-decimal rounding; gate tolerance 0.02.
- **Generator floor constants.** 3 namespaces, 50 topics, 5,000 memories, 1,200 entities, 500 queries, 180 days, dim 64; dedup 0.95, auto-link 0.85, twin cosine [0.86, 0.94], in-topic [0.70, 0.94], cross-topic under 0.30, hub fan-out under 20, neighbor and propagate caps 20, sweep grace 30 d, hard floor 0.02. Frozen after one tuning pass.
- **Supersession runs in all arms.** The arms differ by the decay curve and nothing else; under A a superseded standard is excluded by `scoreAndFilter` but never pruned.
- **Old episodes count as relevant.** Forgetting an old episode is the price of a leaner store, and the table must show that loss.
- **amd64-only baseline.** Go does not fuse multiply-adds on amd64, so Windows and Linux CI agree bit for bit; `WriteBaseline` returns `ErrUnsupportedArch` elsewhere.

</Callout>

### Risks and mitigations

<Table
  id="risks"

  rows={[
    ["Synthetic geometry can be tuned to flatter arm C", "Generator constants are frozen and named; every metric is reported, including episodic recall where B and C lose; multiple seeds; the M6 README states the assumptions; the gate never asserts the thesis."],
